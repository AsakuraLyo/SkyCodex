# SkyCodex 0.1.0 beta 2

天空开拓者的 Codex 角色助手原型，目标版本：Minecraft 1.21.1、NeoForge 21.1.249、Create 6.0.10。

你正常用正版账号登录服务器，Codex 操作当前客户端的同一个角色。无需另一个账号，无需关闭正版验证。游戏必须保持运行。Codex 与游戏需在**同一台电脑**上运行（Windows 或 macOS 均可）；本包不支持跨机器远程控制，例如 Mac 上的 Codex 控制 Parallels 虚拟机里的游戏。

这是可编译的测试版控制工具，不是已经在你的 194 模组服务器通过验收的成品。请先在测试存档完成下面的验收，再用于正式建筑。

## 安装（Windows / macOS）

1. 将整个包解压到固定位置，例如 `D:\SkyCodex`。不要在压缩包内直接运行，安装后不要移动该目录。
2. 安装 [Node.js](https://nodejs.org/) 22 或更新版本。游戏继续使用启动器为 MC 1.21.1 配好的 Java 21；运行这个包不需要安装 Gradle。
3. 关闭 Minecraft。Windows 双击 `01-install.cmd`；macOS 双击 `install-mac.command`（被系统拦截时右键 →“打开”，或在终端运行 `bash install-mac.command`）。安装程序会自动列出常见启动器（HMCL、PCL、官方启动器、Prism、CurseForge、Modrinth）里装有 1.21.1 机械动力的目录，输入编号即可；也可以粘贴路径，Mac 上可以直接把文件夹拖进终端。通过启动器的“打开游戏文件夹”查找，应该能在里面直接看到 `mods`、`config` 等目录。启用版本隔离时，不一定是最外层 `.minecraft`。
4. 安装程序校验并复制 `mods` 内两个 JAR：SkyCodex 和官方 Baritone 1.11.3 NeoForge API 版。它不会替换原有整合包模组。遇到已有其他版本时会停止，避免重复加载。
5. 安装程序向你现有的 `%USERPROFILE%\.codex\config.toml`（macOS 为 `~/.codex/config.toml`） 添加 `skycodex` MCP 配置，有原配置时会备份。若已有同名配置则保留，请参考生成的 `codex-config.toml` 核对。使用 Codex 桌面版或 CLI 的本地 MCP 功能；不保证普通网页聊天会读取这份配置。
6. 重启 Codex。启动天空开拓者、进入测试世界或服务器。运行 `02-check.cmd`（macOS：`check-mac.command`），应显示 `in_world: true`。
7. 游戏内按 **F8** 启用接管；按 **F9** 立即取消任务并交还控制。按键冲突可在 MC 控制设置中的“SkyCodex 角色助手”修改。
8. 在 Codex 打开本包目录作为工作目录，以便读取 `AGENTS.md` 和 `blueprints`。让它先调用 `mc_status`。CLI 可用 `/mcp` 检查 `skycodex` 是否连接。

连接程序通过 MCP 提供游戏操作工具，不直接调用 OpenAI API，不要求 API Key。推理由你登录的 Codex 执行，仍受其账户用量和运行环境限制。

## 第一次怎么说

先发：

> 使用 skycodex 工具读取我的角色状态、背包和附近环境，先不要移动。

再在空旷、无玩家建筑的林地测试：

> 收集额外 8 个橡木原木。使用实际掉落物统计进度，完成后停止。

然后：

> 查询服务器当前配方，用背包里的材料做一个工作台。不够的材料先告诉我缺什么。

再测吃东西和放置：

> 吃一份背包里的食物。然后把工作台放在我脚边一格的空地上，再挖回来。

完成基础验收后可以提出完整目标，例如“收集材料、做铁镐”。Codex 需要把目标分解为工具制作、挖矿、熔炉交互等步骤；不是一个后台程序保证任意任务都能完成。遇到卡住或未知机器界面，应反馈情况，而不是编造成功。

## 使用现成的 .nbt 蓝图（机械动力蓝图／结构方块）

游戏目录 `schematics` 里的 `.nbt` 文件可以转换成 SkyCodex 蓝图：

```
node bridge/nbt.mjs "D:\游戏目录\schematics\某蓝图.nbt" blueprints/某蓝图.json
```

转换器会列出尺寸、材料，以及**不会被施工**的部分：机器和带方块实体的方块（箱子、齿轮、流体管等）、水和岩浆、门、床。转换后让 Codex 用 `mc_check_blueprint`（带 `skip_unsupported: true`）在游戏里再检查一次。这一步以整合包的实际注册表为准，会指出整合包里**没有安装的模组方块**和创造模式专用方块（如屏障）。机器部分需要之后手动放置，或用机械动力的蓝图炮。

## 按参考图片建造

1. 把参考图片发到连接了本包的 Codex 会话，并说明大概尺寸、选址、风格和允许使用的材料。单张图片没有背面及内部信息，隐藏部分需要设计。
2. Codex 在 `blueprints/src` 写一份**设计文件**（`名称.design.json`），用“填充、四面墙、空心盒、木框架、字符画立面、双坡／四坡屋顶”等指令描述建筑，而不是逐块手写。运行 `node bridge/design.mjs blueprints/src/名称.design.json` 生成逐块蓝图 `blueprints/名称.json` 和材料清单。示例见 `blueprints/src/cottage.design.json`。
3. 运行 `node bridge/preview.mjs blueprints/名称.json`，得到 `名称.preview.png`（正面、右侧、背面、左侧、俯视五个视图，每 5 格一条粗网格线，方便和参考图数窗户、对比例）和等轴 `名称.svg`。Codex 应打开 PNG 与参考图对照并反复修改设计。预览使用近似颜色，不是游戏材质或光影渲染。
4. 先看设计预览，再调用 `mc_check_blueprint` 检查真实材料缺口、已完成部分和位置冲突。
5. 采集／合成材料，使所需建筑材料位于背包中，另备约 32 个泥土等**不属于蓝图材料**的方块做脚手架（施工不会把蓝图材料当脚手架消耗），之后调用 `mc_build_blueprint`。角色会正常走动、消耗物品、逐块放置，不能穿墙或无材料生成建筑。
6. `mc_wait` 轮询施工进度；完成条件是所有指定位置的方块与可控属性（朝向、上下半、轴向等）匹配。栅栏/玻璃板连接方向、楼梯拐角形状由游戏根据相邻方块自动决定，不参与比对。再用 `mc_screenshot` 检查外观。若断开或暂停，重新检查同一蓝图可以跳过已经正确的方块。

包内示例 `starter-house.json`：7×7 地基、9 格高度、192 个方块。需要圆石 49、橡木原木 16、橡木木板 60、玻璃 18、云杉木板 49。蓝图原点是地基一角的方块坐标；正 X 为宽度，正 Z 为深度。先清理好地面，保留进出空间。高处施工可能还需要脚手材料和额外通道，蓝图材料统计不包含临时脚手。

蓝图格式：

```json
{
  "name": "示例",
  "blocks": [
    {"x": 0, "y": 0, "z": 0, "block": "minecraft:oak_planks"},
    {"x": 1, "y": 0, "z": 0, "block": "minecraft:oak_log", "properties": {"axis": "y"}}
  ]
}
```

每个相对坐标范围 0–63，单份最多 20,000 个方块。没有写入蓝图的格子保持原样，不能用 `air` 清空建筑。施工会拒绝位置冲突，避免拆掉已有建筑。

## 功能与边界

| 功能 | 第一版实现 |
|---|---|
| 背包、坐标、生命、附近方块、游戏画面 | 客户端实时读取 |
| 寻路 | Baritone，单次目标距离不超过 256 格；不自动挖路；找不到路会立即报告失败 |
| 采集 | 可同时指定多种方块与掉落物（如所有原木），按背包增加量验收；默认只挖暴露在空气中的方块、不会自行开矿道；可搭泥土够高处 |
| 普通合成 | 使用服务器同步的有序／无序配方，模拟槽位点击；一次一种配方；自动打开的工作台会自动关闭 |
| 放置／拆除单个方块 | `mc_place` 放工作台、熔炉、箱子、火把等；`mc_break` 挖掉一个方块并捡起掉落物；容器需先清空 |
| 吃东西 | `mc_eat` 自动挑选营养最高且无负面效果的食物 |
| 箱子、熔炉等 | 提供打开、读取槽位和点击工具，由 Codex 逐步操作并核对结果 |
| 建筑 | 设计文件生成器 + 五视图 PNG 预览、稀疏 JSON 蓝图、材料检查、Baritone 生存施工、方块状态验收 |
| 看图转建筑 | 由当前 Codex 会话理解图片并制作蓝图；没有独立的自动三维重建模型 |
| Create 机器／航空学载具 | 不保证自动组装或操作；机器配方查询不代表具备对应制造技能 |
| 战斗、自动吃饭（需 Codex 主动调用 mc_eat）、跨维度、任意整合包任务 | 未实现完整自动策略 |

普通合成支持标准 shaped/shapeless，特殊动态配方及机器加工不能通过 `mc_craft` 执行。3×3 合成需要附近可触及的工作台。这里读取的是游戏当前同步的配方（已包含整合包 KubeJS 脚本的修改），一律以 `mc_recipes` 的结果为准。

蓝图第一版拒绝方块实体（机器、箱子等）、液体、含水状态、门和双层台阶（`skip_unsupported: true` 时跳过并列出）。楼梯、台阶、原木、按钮等的朝向、上下半、轴向会照蓝图放置：Baritone 放不出正确朝向时，SkyCodex 会自己走到合适的位置、看向正确的面再放。连接方向、打开/点燃/通电这类布尔状态和作物生长阶段不参与比对。不能把移动飞船上的坐标当作静态世界坐标使用。

## 停止和故障

- **F9**：取消当前任务、解除控制。恢复需在游戏按 F8，再提交任务。当前版本不会自动续跑被取消的合成点击序列。
- 如果停止时鼠标仍拿着物品，请在背包里放下再继续；程序不会把它丢出。
- 断开工具心跳超过 60 秒、死亡、离开世界、跨维度会关闭接管。生命值不高于 8（4 颗心）或饥饿值不高于 6 时，新任务拒绝启动、进行中的任务停止，但接管保持开启，Codex 可以先调用 `mc_eat` 再继续。
- 单个任务默认 180 秒，上限 600 秒。超时会失败并停止，不会无限挖矿或施工。
- 打开 GUI 会停止寻路／采集／施工。合成和打开容器任务允许相应 GUI。操作期间尽量不要同时手动移动或点击。
- 单人游戏切换窗口后若暂停，关闭“失去焦点时暂停”（常用 F3+P），或保持窗口正常运行。不要在暂停菜单停留时等待机器人执行。
- `Cannot read the game connection file`：检查实际游戏目录，确认 SkyCodex 已加载。`02-check.cmd` 只读本机状态，不需要服务器地址和密码。
- `Control disabled`：在游戏里按 F8。`Missing crafting ingredients`：先查配方和背包。`Build location contains conflicting blocks`：先选一个无冲突位置。
- 若启动崩溃：关闭游戏，将本包新增的两个 JAR 移出 `mods` 即可撤回；保留报错日志用于排查。本版没有修改服务器或存档文件。

## 源码、验证和依赖

源码位于 `source`。构建需要 Java 21 与 Gradle Wrapper，进入 `source` 后运行 `gradlew.bat build`（macOS：`./gradlew build`），再运行 `node scripts/package.mjs` 生成安装包。桥接协议与蓝图生成器测试：`node --test bridge/test.mjs`。验证记录与开发进度见 `VALIDATION.md`；在 Windows 上继续开发、运行开发版客户端冒烟测试见 `Windows开发指南.md`。

Baritone 是官方 1.11.3 NeoForge API 发行物，模组内部 ID 为 `baritoe`（不是文件名拼写错误）。许可证及对应源代码见 `third_party`。本项目自身代码采用 MIT 许可证。

参考文档：[Codex MCP](https://developers.openai.com/codex/mcp/)、[NeoForge 1.21.1](https://docs.neoforged.net/docs/1.21.1/)、[Baritone 1.11.3](https://github.com/cabaletta/baritone/releases/tag/v1.11.3)。
